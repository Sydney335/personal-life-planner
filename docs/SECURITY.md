# Privacy & data handling / 隐私与数据管理

- **Data location:** your chosen Supabase project region, plus IndexedDB in each browser profile. Auth session tokens are persisted by the Supabase browser client. Hosting providers may keep infrastructure/access logs. No diary content is intentionally sent to the static host, AI, analytics, CDNs or crash-reporting vendors.
- **Threat model:** RLS and table grants isolate authenticated accounts. Neither ordinary users nor anonymous users can bypass revision checks through direct table writes. The RPC uses `auth.uid()`, checks the expected account, locks the record and performs compare-and-set atomically. IDs are scoped by `(user_id,id)`. Service/admin keys bypass RLS and must stay out of this application.
- **Encryption limits:** HTTPS in transit, provider-managed database security, no client-side end-to-end encryption. The provider and project administrators may read cloud content. Anyone with access to an unlocked browser profile, malicious same-origin script or a device backup could access cached records/session tokens. Use device locks and trusted hosting. Never promise medical-record compliance.
- **Local persistence:** IndexedDB stores local edits before a network request. Cloud-authenticated sign-out blocks while changes/conflicts remain, and clears that account's device records after success. Guest records are retained when leaving guest mode. Clear this device's local data is explicit; it does not delete cloud records. Export first. Clearing browser site data also removes the guest data/outbox.
- **Offline/auth:** an already authenticated, loaded device can edit offline. It cannot first log in offline. Expired credentials may need reauthentication when online before queued edits upload. No user identity is derived from an email supplied in a write request.
- **Sync:** account-scoped Realtime hints + 15-second polling + focus/reconnect. iOS suspends background web apps; changes reach a suspended device when it opens again. There is no guaranteed background sync or push. UI Saved means the current known local queue has been acknowledged, not that another suspended device has already downloaded it. Transient network/RLS errors keep edits queued and display Sync Error.
- **Conflict resolution:** revisions are per record. Concurrent changes to the same record, including deletion, are not silently overwritten. Both versions remain in IndexedDB until explicitly resolved; a lost response uses mutation IDs to prevent duplicate versions. Notes may combine main text; reflected fields remain from the selected device version when combining and both full payloads are visible in the comparison. Review those fields too. Separate tasks avoid conflicting on a whole day's document. Accepted server versions remain in `planner_history`.
- **Backups:** JSON contains plaintext. Regular export includes live current records, not auth sessions, deleted records or all cloud historical revisions. Unresolved conflicts block normal export; resolve them or separately copy both versions first. Import validates version, dates, IDs and payloads, rejects duplicate IDs, and imports missing records only. Different existing records (including tombstones) are skipped and counted. Keep old backup files for manual recovery; importing is not a destructive rollback. A person with a downloaded backup can read it.
- **Server history / recovery:** authenticated users can SELECT their own `planner_history`; there is no normal table write access. To recover a previous payload, use the project SQL editor as its trusted owner, or a securely authenticated account query, inspect that account and record, and restore through `save_planner_record` using the **current** revision and a fresh mutation UUID. Never disable RLS, expose history publicly, or place admin keys in frontend code. A history browsing/recovery UI remains future work.
- **Deletion:** app deletion writes a synced tombstone, preserving offline conflict safety and revision recovery. It is not permanent erasure. For permanent erasure, the project owner deletes the Auth user via Supabase's trusted dashboard; foreign-key cascades remove the account's records/history. Clear local browser data on every device and delete exported backups separately. The app does not yet provide self-service account deletion.
- **Retention:** no automatic history pruning; plan storage/retention with the selected free-tier limits. Free-tier cloud sync is not an independent backup or availability guarantee. Keep encrypted device/file backups of regular exports and consider provider database backups if needed.
- **Headers:** `vercel.json` restricts scripts/objects/frames and connections. Inline styles are allowed for React chart geometry; scripts remain same-origin only. Never serve untrusted user-provided JavaScript from this origin. Supabase URLs/keys are public configuration, not authentication to private records. Account permissions come from the session and RLS.
