# 字体、手动填写日期分类与删除线

这是现有日光应用的增量更新。代码和数据字段使用英文；中英文界面的分类含义完全一致。分类是用户对主观日期的认定，与任务状态、系统日期、午夜、时区或实际时间戳无关。

## 使用方法

- **设置 → 字体大小**：选择小（80%）、中（100%）、大（120%）、特大（160%），或用滑块在 80%–160% 间逐步调整。预览与应用正文立即变化；“恢复默认设置”恢复 100%。
- **设置 → 填写日期颜色**：“前一天填写”和“当天填写”各有独立的 20 色预设色板，也可使用自定义颜色选择器或 HEX 输入。支持 `#RRGGBB` 和 `#RGB`；无效输入会提示，不会覆盖已保存的有效颜色。每个分类可独立恢复默认颜色。
- **颜色预览**：同时显示浅色、深色背景上的实际文字。普通文字对比度低于 4.5:1 时提示，但保留用户的选择。
- **任务编辑 → 填写时间分类**：手动选择“前一天填写”“当天填写”或“不标记”。新任务和旧数据默认“不标记”。即使凌晨两点填写，仍可自由选择任何类别；系统绝不自动选择或更改。
- **计划页和日记页顶部图例**：随所选计划日期、颜色和语言更新。参考日期只解释手动类别，绝不是对真实填写日期的验证。
- **删除线**：前一天填写的任务可在编辑窗口或任务行中切换删除线；再次点击即撤销。文字仍能编辑，类别颜色保留，完成状态不变。改为当天填写或不标记时隐藏删除线效果，底层状态保留；改回前一天填写时恢复。
- **日记段落**：每个编辑块是一个可独立分类和设置删除线的段落。点击“添加段落”新建默认不标记的段落。需单独标记一句话时，将该句放在独立段落中。段内换行保持为同一编辑块；旧日记按空行分段，原文保持不变。
- **同步与备份**：字体、两种分类颜色、任务分类、删除线和日记段落数据均通过现有 IndexedDB → Supabase 流程保存。同账号设备之间同步；本机体验模式仍只保存到本机。离线编辑在联网后排队同步。
- **冲突处理**：沿用现有版本比较机制，展示本机和云端两份数据。日记可将双方段落保留在合并草稿中，并在保存前继续编辑文字、分类和删除线；回顾字段沿用本机版本。分类和颜色偏好发生冲突时，需明确选择保留哪份设置。合并内容超出原有日记字数限制时会报错，冲突保持待处理。
- **打印 / PDF**：设置中选择彩色打印或黑白打印。填写版保留图例、任务/段落分类文字标签与删除线；黑白模式依靠文字标签区分类别。屏幕 80%–160% 对应打印 90%–130%，使纸张上的字号更实用。空白手写版不显示填写分类标签。长内容可续页，因此填写版整周不保证固定为 14 页。

## 本机设置与验证

需要 Node.js 24（也支持 `^22.12.0`）和 Chromium。

```sh
npm ci
cp .env.example .env.local
# 在 .env.local 中填写现有 Supabase 项目的公开 URL 和 publishable/anon key。
npm run dev
```

继续使用已有 Supabase 项目、认证和环境变量。无需新建项目或重建数据库；本机体验无需云端配置。

```sh
npm run check
npm test
npm run test:e2e
npm run build
```

Playwright 默认使用 `/usr/bin/chromium`，其他路径可设置 `CHROMIUM_PATH`。完整部署说明见 [SETUP.zh-CN.md](SETUP.zh-CN.md)。

## Supabase 迁移：需要执行什么 SQL

**现有生产项目只执行新增文件 `supabase/migrations/002_entry_presentation.sql`，不要重新执行 `001_planner.sql`。本次开发没有操作生产数据库。**

1. 打开现有项目的 Supabase Dashboard → SQL Editor → New query。
2. 将仓库中 `supabase/migrations/002_entry_presentation.sql` 的完整内容粘贴进去。
3. 点击 Run，确认成功。此迁移只执行一次；如果已经通过 Supabase CLI 的迁移流程执行，就无需再次手动运行。
4. 迁移保留已有表、记录、RLS、版本历史和同步 RPC。它新增 `created_at` 列，并把 JSONB 单条记录上限从 1 MiB 扩为 4 MiB，容纳长篇中文日记的段落数据与搜索文本。
5. 旧记录创建时间未知，保留 `NULL`；不以更新时间倒推。新记录的 `created_at` 是服务器首次接收插入的时间，离线创建时可能晚于实际输入。`updated_at` 继续由现有同步函数维护。这些时间都不参与主观分类或颜色计算。
6. 全新数据库先依次执行 `001_planner.sql`、`002_entry_presentation.sql`。使用 CLI 的项目可按现有迁移流程执行 `supabase db push`，无需 SQL Editor 重复执行。

新增功能数据在已有 JSONB payload 中存储，无需对旧任务或日记批量改写。旧记录读取时安全补齐默认值。迁移后，按既有审批流程审核 PR；获得授权后再合并、部署。各设备首次使用新功能前应刷新应用，保证编辑器版本一致。

## 验证范围和限制

新增自动化覆盖手动分类、午夜行为、字体/颜色设置、段落格式、备份恢复、离线/重连、两设备存储的同步契约、冲突合并、迁移、中文和英文、三种屏幕尺寸与 Chromium PDF。结果详见 [ENTRY-PRESENTATION-TESTING.md](ENTRY-PRESENTATION-TESTING.md)。

真实 iPhone/iPad/Mac 上的 Safari/PWA、系统颜色选择器和系统打印需在预览版本上验收。跨设备测试使用同步协议测试替身；本次环境没有可用的 Supabase 测试账号，未声称已实测真实云端登录、Realtime 或三台 Apple 设备同步。极低对比度的自定义颜色仍由用户负责选择；应用不会改写颜色。
